S. No. Terms Definition
1 LEI LEI is an acronym for Legal Entity 
Identifier. The Legal Entity Identifier (LEI) is 
a 20-character, alpha-numeric code based 
on the ISO 17442 standard developed by 
the International Organisation for 
Standardization (ISO). It connects to key 
reference information that enables clear 
and unique identification of legal entities 
participating in financial transactions.
2 Lite participants The participants of the organisations that 
have been included in OSTTRA 
Documentation Centre database but do not 
have direct access to the services of OSTTRA 
Documentation Centre. Hence, the Lite 
participants' activities such as Approval 
and Rejection take place through the 
respective emails.
3 Online participants The participants of the organisations that 
have been included in OSTTRA 
Documentation Centre database and have 
direct access to the services of OSTTRA 
Documentation Centre.
4 Organisation An organisation included in the OSTTRA 
Documentation Centre database from the 
Global Legal Entity Identifier Foundation 
(GLEIF) database.
5 Tenor The time duration after which the validity of 
a traded document in Foreign Exchange 
(FX) expires.

2 Introduction
OSTTRA Documentation Centre (ODC) is an online repository of the digital versions of the documents. It incorporates

workflows. OSTTRA Documentation Centre also supports multiples operations on the different versions of a digital 
document and thus provides a complete solution for online document creation, approval, maintenance, and termination.

1 Introduction
OSTTRA’s Documentation Centre (ODC) is a new version of our original Designation Notice Manager (DNM) service.
The new service supports the management of additional agreement types, in addition to the Designation Notices type 
available in DNM.
ODC provides a broad range of new capabilities and functions, which are designed to provide an enhanced user 
experience and promote greater interoperability with downstream systems through the provision of a comprehensive suite 
of APIs. API access to documents stored within ODC removes the need for the double entry of the information, which is 
prone to errors and requires additional reconciliation processes to ensure integrity.
This guide provides information regarding the main communication channels that ODC supports:
 
Notifications service (Event Driven Document Changes) - Events based service (“Push”) that informs customers 
about the updates related to their documents.
 Events generated signify that a document has been updated
 Full document details pushed to receiver 
 Typically delivered using JSON over Message Queue (MQ) or SFTP

Software  Package  8  (Drop  3d)  
The  following  covers  package  8  of  software  deliverables  -  ODC  version  26.4.0.  
General   
General  Description  
Static  TND  as  a  non-deliverable  currency  is  now  available  in  the  system  for  selection.  
Approval  Workflows  
Users  can  now  implement  approvals  whereby  the  prime  broker  can  manage  offline  manual  agreement  approvals  by  executing  brokers  by:  ●  setting  up  specific  ‘on  behalf  of’  manual  approval  groups,  ●  the  ODC  system  generating  bespoke  or  standard  agreement  PDF’s  sent  to  nominated  email  accounts,  ●  prime  broker  users  approving  agreements  on  behalf  of  executing  brokers  once  agreed  and  approved  offline.  During  the  approval  process,  users  are  now  prevented  from  undertaking  multiple  levels  of  approval  for  an  agreement  where  a  firm  has  been  operationally  set  up  with  several  approval  groups  and  users  belong  to  2  or  more  of  the  groups.  Note :  Approval  groups  used  for  approving  on  behalf  of  an  executing  broker  are  excluded  from  this  processing.  
Draft  Versions  The  system  now  only  allows  one  single  draft  version  of  an  agreement  to  be  inflight  at  any  one  point  of  time  to  optimise  the  management  of  Designation  Notices  and  4  Ways  agreements  for  users.  
Agreement  Editing  
Agreements  in  an  ‘In-approval’  or  ‘Approved’  state  are  editable  by  users.  Edits  can  be  applied  on  an  individual  agreement  basis  or  in  bulk.  
 
Agreement  Types   
Agreement  Type  Description  
Designation  Notices  (DN’s)  
Designation  Notices  can  now  be  created  against  client  counterparties  where  the  client  combines  multiple  legal  entities  to  form  a  single  complex  combined  counterparty  to  represent  the  client.  The  formulated  client  counterparty  is  then  used  on  the  DN  and  for  subsequent  integration  with  CreditLink  for  credit  management.  The  name  of  the  currency  group  used  to  create  required  authorization  scope  are  now  shown  by  system  when  viewing  each  DN  agreement.
